# オブジェクト指向

## この章で学ぶこと

- オブジェクト指向の考え方を理解する
- オブジェクト指向が必要になった理由を理解する
- クラスとオブジェクトの関係をイメージできるようになる


## オブジェクト指向とは

オブジェクト指向（Object Oriented Programming）は、現実世界のモノや概念をプログラムとして表現する考え方である。

例えば、

- ユーザー
- 商品
- 注文
- 社員

などをプログラム上で表現する。



## オブジェクト指向がない場合

例えばユーザー情報を管理するプログラムを考える。

```text
ユーザー1
名前：田中
年齢：20

ユーザー2
名前：鈴木
年齢：25

ユーザー3
名前：佐藤
年齢：30
```

オブジェクト指向がない場合、

```java
String user1Name;
int user1Age;

String user2Name;
int user2Age;

String user3Name;
int user3Age;
```

のような変数が大量に必要になる。

ユーザーが100人、1000人に増えると管理が難しくなる。



## オブジェクト指向を利用した場合

ユーザーという共通の概念をまとめて表現できる。

```text
User
 ├─ 名前
 └─ 年齢
```

これをクラスとして定義する。

```java
public class User {
}
```

すると、

```text
田中
鈴木
佐藤
```

などのユーザーを同じ仕組みで管理できる。



## 現実世界で考える

オブジェクト指向では、現実世界のものごとをモデルとして考える。

例)

```text
自動車
 ├─ 色
 ├─ メーカー
 └─ 速度
```

```text
社員
 ├─ 社員番号
 ├─ 名前
 └─ 部署
```

```text
商品
 ├─ 商品コード
 ├─ 商品名
 └─ 金額
```

プログラムでも同じように考える。



## オブジェクト指向の目的

オブジェクト指向には以下の目的がある。

### 1. 再利用しやすくする

同じ仕組みを何度も利用できる。



### 2. 保守しやすくする

変更箇所を少なくできる。



### 3. 理解しやすくする

現実世界に近い形でプログラムを表現できる。



## オブジェクト指向の代表的な考え方

オブジェクト指向には代表的な考え方が存在する。

### カプセル化

データと処理を1つにまとめる考え方。



### 継承

既存クラスの機能を引き継ぐ考え方。



### ポリモーフィズム

同じ操作でも異なる振る舞いを実現する考え方。



本研修では後続の章で学習する。

現時点では、

```text
現実世界のモノをプログラムで表現する考え方
```

と理解しておけばよい。



## TERASOLUNAとの関係

TERASOLUNA Frameworkもオブジェクト指向を前提として構成されている。

例)

```text
UserController
UserService
UserRepository
User
```

これらはすべてオブジェクト指向の考え方に基づいて設計されている。

- オブジェクト指向により再利用性と保守性が向上する
- TERASOLUNAもオブジェクト指向を前提としている
